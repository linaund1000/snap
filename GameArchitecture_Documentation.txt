GAME REQUIREMENTS ARCHITECTURE
==============================

1. BASE DOCUMENTATION
---------------------
[Docs]
The project is a Photography & Social Simulation Game (GPOyun) set in a Mediterranean town square. It focuses on the cybernetic feedback loop between the player's photography (journalism) and the autonomous social dynamics of the NPCs.
The core engine is built in Unity using C#.

[Current Architecture]
The architecture relies on a centralized Singleton Manager pattern for system orchestration, avoiding excessive EventBus abstraction in favor of direct method calls.
Core Managers:
  - GameManager: Orchestrates overall game states (Playing, Paused).
  - TimeManager: Manages time-of-day phases (Morning, Midday, Afternoon, Evening, Night) and triggers phase-specific system events.
  - NewspaperManager: Collects captured photos, creates news editions, and distributes them to NPCs.
  - NPCManager: A registry for all active NPCs.
  - RelationshipMatrix: A centralized bidirectional memory matrix storing relational integers [-100 to 100] and textual opinions between all NPC pairs.

2. SCENARIOS & USE CASES
------------------------
[Scenarios for Game]
Scenario A: The Gossip Catalyst
1. Player photographs NPC A arguing with NPC B.
2. Photo is published as a "Scandal".
3. Next morning, NPC C reads the paper, lowers opinion of NPC A, and triggers an Angry emoji.
4. NPC A's relationship with the Player drops significantly.

[Use Cases]
- Take Picture: Player aims Viewfinder, validates Subject, captures RenderTexture, calculates CompositionScore, saves PNG.
- Publish News: System aggregates yesterday's photos, selects best/worst, generates headlines, stores in History.
- Read News: NPC walks to NewspaperBoard, reads pending news, evaluates emotional reaction via AppraisalEngine, updates MemoryStream.
- Gossip / Socialize: UtilityAI triggers two NPCs to meet, exchange opinions based on RelationshipMatrix, and modify their mutual Needs.
- React to Player: SensoryMatrix detects Camera Flash/Aim, AppraisalEngine checks Neuroticism/Agreeableness, NPC poses or flees.

4. STATE & BEHAVIORAL MODELING
------------------------------
[Finite State Machine of Game]
States: Loading -> Playing <-> Paused -> GameOver
Transitions: Controlled explicitly by GameManager.ChangeState().

[Finite State Machine of Objects (NPCController)]
States: Idle, Wandering, WalkingToBoard, Reading, Reacting, WalkingHome, Sitting, Hugging, Fleeing, Socializing
Transitions:
  - Reading -> Reacting (After processing NewsPublishedData)
  - Reacting -> WalkingHome (After posing or expressing anger)
  - Controlled largely by UtilityAI overriding the current state through Action interrupts.

[Utility AI State Transition Logic]
Needs (Boredom, SocialDesire, Energy, Introversion) naturally decay/grow over time.
Actions (WanderAction, GossipAction, etc.) calculate a Utility Score based on Needs.
The ActionPlanner evaluates utilities every 1 second. If a new Action exceeds the current Action's utility by a buffer margin, the current action is interrupted.


5. SYSTEM FEEDBACK & HCI
------------------------
[Cybernetic Core Loop]
1. Player Observation: Player navigates world, observing NPC behaviors and social clusters.
2. Player Action: Player captures a photograph (Stimulus).
3. System Process: CameraController -> PhotoData -> NewspaperManager -> NewsStory.
4. System Feedback: News is distributed at Morning phase. RelationshipMatrix recalibrates global opinions.
5. NPC Reaction: NPCs spawn emojis (💔, ⭐, 🥰, 🤬), alter paths, and change behavior towards Player. Loop restarts.

[Stimulus-Response Matrix]
Stimulus: Camera Flash -> Appraisal: High Extraversion -> Response: Pose, Happy, +10 Player Rel.
Stimulus: Camera Flash -> Appraisal: CameraShy Instinct -> Response: Flee, Fearful, -30 Player Rel.
Stimulus: News Scandal -> Appraisal: Target is Self -> Response: Angry, -40 Player Rel.
Stimulus: Friendly Greeting -> Appraisal: Normal -> Response: Happy, +5 Rel.


6. DETERMINISTIC LOGIC & CONSTRAINTS
------------------------------------
[Transfer Functions & State-Space Models]
Need Decay: NewValue = Clamp(OldValue + (Rate * Time.deltaTime), 0, 100)
Relationship Delta: NewRelation = Clamp(OldRelation + Delta, -100, 100)
News Reaction Delta (Example: Agreeable NPC reading Happy News):
  Delta = Round(25 * ReactionIntensity * (1 + Agreeableness))

[Boundary Condition Specifications]
- Relationships: Hard clamped between -100 (Rival) and +100 (Best Friend).
- Needs: Bounded [0, 100].
- Time: 24-hour cycle modulo, mapped to 5 discrete DayPhases.
- Camera: Cooldown timer restricts rapid-fire shutter spam to prevent RenderTexture memory overflow.

[Timing / Data Flow]
- Update loop: NPCActionPlanner evaluates every 1.0s (staggered by random offset per NPC to spread CPU load).
- TimeManager advances phase every 120s real-time. Morning phase explicitly invokes NewspaperManager.OnMorningArrived() which clears yesterday's photo buffer.


7. DEPLOYMENT & INFRASTRUCTURE
------------------------------
[Deployment Topology]
- Application: Standalone local Unity Executable.
- Storage: 
  - Photos are serialized as PNGs directly to the OS file system (`Application.dataPath/_Game/CapturedPhotos/`).
  - Saved using a structured schema: `{UUID}_{Timestamp}_{Subject}.png`.
  - Social memory/state relies on runtime memory (Dictionary), awaiting permanent Save/Load serialization to JSON.
- Input: Unity New Input System (WASD + Mouse for Look, Tab for Gossip UI). No legacy Input.GetAxis dependencies.
